# Demo: screenshots of the real app (V10-06S)

The `v-*.png` images in `docs/assets/screenshots/` are screenshots of V's interface
actually running, with no mock-ups. They are generated by a script, so they can be
redone when the UI changes. Every one is in English with the Carbon White theme,
except the library, which shows the optional Material 3 skin (light).

**Date:** 2026-10-21. **Base commit:** `034e178`. **Machine:** Linux, Bazzite
`bazzite-nvidia-open` (Fedora 44, kernel 7.2.9), NVIDIA GeForce RTX 4060 Laptop,
Chrome 155 (flatpak) in headless mode, 1440 px wide window.

## What data is used

- **Audio:** three short recordings generated on the spot with Kokoro (sherpa-onnx,
  CPU) from invented English text, synthetic voices only; nobody's recording and
  no real names. `product-sync.wav` (22 s) is a two-person meeting about launching
  an open source audio library (voices `af_heart` and `am_michael`, alternating);
  `podcast-intro.wav` (10 s, `am_adam` and `af_bella`) and `lecture-notes.wav`
  (6 s, `af_sarah`) only fill the library.
- **Transcription:** Faster Whisper `base` on GPU (CUDA, float16), real, with the
  "Fast" profile and automatic language. The model is imported through the API
  (`POST /api/models/faster-whisper:base/install` with `method=import`,
  `origin=buzz`) from the Hugging Face cache that already exists on the machine
  (`BUZZ_MODEL_ROOT`): a read-only hardlink, nothing is downloaded or modified.
  Each job took 1 to 3 seconds.
- **Speakers:** the sherpa-onnx diarization models (pyannote segmentation 3.0 and
  WeSpeaker ResNet34), copied into the temporary data folder with the same manifest
  an install writes. "Product sync" and "Podcast intro demo" ask for automatic
  speaker detection; "Lecture notes demo" does not, so its library row says 0
  speakers.
- **Speech synthesis:** Kokoro multi-lang v1.0 (int8), imported from a local folder
  through the custom-model import (`POST /api/models/custom/preview` with
  `source_type=folder`, then `/install`); V copies the files and validates them,
  the original folder is not changed. That is why it appears as "Kokoro
  multilingual v1.0". The phrase is synthesized on CPU in about 4 seconds.
- **V data:** a temporary directory with its own `XDG_*`, a temporary `HOME` for
  the server (so it does not find model copies in the real home folder) and a free
  port (never 8765); the script never touches `~/.local/share/voz`, `~/.config/voz` or
  `~/.local/state/voz`, and deletes it when done. The server is always shut down
  (`trap`).

The transcribed text in the screenshots is real model output, untouched. In this
run "Product sync" came out as nine segments: «Good morning, everyone.», «Today,
we need to plan the launch of the Open Source Audio Library.», «Sounds good.»,
«I finished the documentation draft yesterday,», «and the examples are ready for
review.», «Great, let's freeze the features on Friday», «and publish the first
release next Tuesday.», «Agreed, I will write the release notes» and «and check
the test results before then.» GPU runs can split the segments slightly
differently from one run to the next.

### What these screenshots do not show

- **A job in progress.** With the GPU the jobs finish in 1 to 3 seconds; the
  workspace shows the completed job.
- **The pasted link next to its result.** After Check link the dialog replaces the
  link field with the review, so the link itself is not visible. The check only
  reads repository metadata; the installation is never confirmed and no weights are
  downloaded (the script lists the installed models at the end).
- **The speaker and speech synthesis tables of the model manager.** The capture
  stops after the transcription table; some catalog names further down are not
  translated yet.
- **Colors chosen by hand.** The speaker colors are the defaults; the browser's
  color picker does not open in headless mode.
- Nothing cloud: no keys are configured and no provider is called.

## Regenerating them

```bash
CAPTURE_KOKORO_DIR=/path/to/kokoro-int8-multi-lang-v1_0 \
CAPTURE_DIARIZATION_DIR=/path/to/diarization-onnx \
scripts/capture-screenshots.sh                 # writes the v-*.png in docs/assets/screenshots/
```

A different output folder can be passed as the first argument. Requirements: `uv`
with the project environment already synced (`asr-local` and `diarization` extras;
the latter also brings sherpa-onnx for speech synthesis. The script starts the
server with `uv run --no-sync` so as not to remove them), `node` 22 or later, `ffmpeg`, `curl`, Chrome in flatpak
(`com.google.Chrome`), network access for Check link, and three local models:

- `CAPTURE_KOKORO_DIR`: the extracted `kokoro-int8-multi-lang-v1_0` folder (read
  only).
- `CAPTURE_DIARIZATION_DIR`: a folder with `pyannote-segmentation-3-0.onnx` and
  `wespeaker_en_voxceleb_resnet34_LM.onnx` (copied).
- Faster Whisper `base` in the Hugging Face cache (`BUZZ_MODEL_ROOT`, by default
  `~/.cache/huggingface/hub`).

It takes about one minute. Optional variables: `VOZ_CMD`, `CAPTURE_MODEL` (default
`base`), `BUZZ_MODEL_ROOT`, `CAPTURE_HF_LINK` (default the Systran link above) and
`CHROME_CMD` (default `flatpak run com.google.Chrome`).

How it works, in case it needs maintenance:

- Routes are hash-based (`#/`, `#/nueva`, `#/t/<id>`, `#/speak`, `#/modelos`), but
  the import and the configurations live in memory, so the UI is driven with
  Chrome's DevTools Protocol (CDP) from `scripts/capture-screenshots.mjs` (Node's
  WebSocket and `fetch`, no dependencies): it imports each audio by injecting a
  `File` into the file field, types names and text with CDP keyboard events, clicks
  the real buttons and switches, and crops the panels
  (`section[aria-labelledby="…-title"]`). Native `<select>` lists do not open in
  headless mode, so the script picks the option and sends the same `change` event.
- The UI reads its language, theme and design from `localStorage`: the script sets
  `voz.lang=en`, `voz.theme=white` and `voz.design=carbon` before loading. The
  Material 3 skin for the library is chosen from the Settings menu and switched back
  afterwards.
- Chrome's profile is created in `~/Downloads/voz-capture-chrome.*` because the
  flatpak sandbox can only write there; it is deleted when done. The audio does
  not go through the browser's disk, so permissions need not be widened.
- The temporary data directory is created under `~/.cache/voz-capture.*` to be on
  the same filesystem as the model cache (hardlinks do not cross filesystems).
- The segment list height depends on the window height (`vh`): the workspace
  capture sizes the window to the whole page. For the speakers crop the script
  tries no filter and a filter per speaker, and keeps the one where the player and
  the Speakers panel start closest to the same height.
- If the UI changes (panel ids `options-title`, `job-title`, `audio-title`,
  `segments-title`, `speakers-title`; the classes `.voz-options`,
  `.voz-diarization`, `.voz-library`, `.voz-export`, `.voz-models`,
  `.voz-speak-result`; the English button labels and the header buttons by their
  accessible name), adjust the `.mjs`. With `CHROME_NO_SANDBOX=1` it adds
  `--no-sandbox` (for a local Chromium instead of the flatpak Chrome).
