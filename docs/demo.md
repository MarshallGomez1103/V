# Demo: screenshots of the real app (S16.02)

Every image in `docs/assets/screenshots/` is a screenshot of V's interface
actually running, with no mock-ups. They are generated by a script, so they can be
redone when the UI changes. (The product was called VOZ when they were taken; the
captures still show that name.)

**Date:** 2026-10-03 (Carbon UI with themes, accents, Spanish/English, live
progress and a speaker timeline; captures in dark theme, Spanish except for 09).
**Base commit:** `46f2e1d` (plus the uncommitted changes of wave 5c-2 in the
working tree). **Machine:** Bazzite `bazzite-nvidia-open` (Fedora 44, kernel
7.2.7), NVIDIA GeForce RTX 4060 Laptop, Chrome 154 (flatpak) in headless mode,
1440 px wide window.

## What data is used

- **Audio:** `reunion-demo.wav`, 17 s, generated on the spot with `espeak-ng`
  (Spanish, two alternating synthetic voices, `es+f3` and `es+m3`). It is nobody's
  recording.
- **Engine:** Faster Whisper `turbo` on GPU (CUDA, float16), real. The model is
  imported through the API (`POST /api/models/faster-whisper:turbo/install` with
  `method=import`, `origin=buzz`) from the Buzz cache that already exists on the
  machine: a read-only hardlink, nothing is downloaded or modified.
- **V data:** a temporary directory with its own `XDG_*`; the script never touches
  `~/.local/share/voz`, `~/.config/voz` or `~/.local/state/voz`, and deletes it
  when done. The server is always shut down (`trap`).

The transcribed text in the screenshots is real model output, untouched (in this
run, the first segment came out as «…repasar la entrega en el proyecto de
ingeniería», although the spoken text said «…entrega del proyecto…»).

### What these screenshots do not show

- **Separated speakers (without `CAPTURE_DIARIZATION_DIR`).** The capture
  environment is a temporary folder without the `diarization:sherpa-default` model
  (it is not downloaded for the captures). That is why the speakers panel comes out
  empty and the timeline is not visible; the download notice (`03`) is. With
  `CAPTURE_DIARIZATION_DIR` pointing to a folder with that model (it is copied to
  the temporary directory, never modified) the transcription asks for speakers and
  `14-hablantes.png` is generated.
- **Words with timing.** The segment is made of clickable words (37 in this demo,
  checked in the DOM by the script), but visually they read as normal text: the
  current word is only highlighted during playback.
- Nothing cloud: no keys are configured and no provider is called.

## Regenerating them

```bash
scripts/capture-screenshots.sh                 # rewrites docs/assets/screenshots/
scripts/capture-screenshots.sh /other/path     # alternative output
```

Requirements: `uv` with the project environment already synced (`asr-local` extra:
the script starts the server with `uv run --no-sync` so as not to remove it),
`node` 22 or later, `ffmpeg`, `espeak-ng`, Chrome in flatpak (`com.google.Chrome`)
and the `turbo` model in the Buzz cache. Without that model the script warns and
only takes the captures that do not need it (`01` and `11`; this path has not been
tested). It takes about 10 seconds. Optional variables: `VOZ_CMD`, `CAPTURE_MODEL`
(default `turbo`), `CHROME_CMD` (default `flatpak run com.google.Chrome`) and
`CAPTURE_DIARIZATION_DIR` (speaker model folder, optional; see above).

How it works, in case it needs maintenance:

- Routes are hash-based (`#/`, `#/nueva`, `#/t/<id>`, `#/modelos`,
  `#/proveedores`), but the import and the configurations live in memory, so
  `chrome --screenshot` only serves for standalone screens. The rest is driven with
  Chrome's DevTools Protocol (CDP) from `scripts/capture-screenshots.mjs` (Node's
  WebSocket and `fetch`, no dependencies): it forces `prefers-color-scheme: dark`,
  imports the audio by injecting a `File` into the file field, picks the engine,
  clicks Transcribe and crops each panel
  (`section[aria-labelledby="…-title"]`). If those ids or classes of the UI
  change, the script's selectors must be adjusted.
- Chrome's profile is created in `~/Downloads/voz-capture-chrome.*` because the
  flatpak sandbox can only write there; it is deleted when done. The audio does
  not go through the browser's disk, so permissions need not be widened.
- The temporary data directory is created under `~/.cache/voz-capture.*` to be on
  the same filesystem as the Buzz cache (hardlinks do not cross filesystems).
- Segment rows use `content-visibility: auto`: only what is in view is painted, so
  the transcript capture scrolls before cropping.
- If the UI changes (panels `options-title`, `extras-title`, `job-title`,
  `audio-title`, `segments-title`, `props-title`, `review-title`, the classes
  `.voz-models`, `.voz-library`, `.voz-export` and the header buttons by their
  accessible name), adjust the `.mjs`.
- The UI picks its language from the browser: the script sets `voz.lang=es` in
  `localStorage` before loading. With `CHROME_NO_SANDBOX=1` it adds `--no-sandbox`
  (for a local Chromium instead of the flatpak Chrome).
